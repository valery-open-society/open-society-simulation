# Contributing

Thank you for your interest in Open Society Simulation. The project is at an early, pre-implementation stage. Contributions that clarify the research question, model assumptions, measures, and project practices are especially useful now.

## Before proposing a change

For a new feature, model, or major change in direction, open an [issue](https://github.com/valery-open-society/open-society-simulation/issues) first. Describe:

- the question or problem the proposal addresses;
- its assumptions and intended scope;
- how its claims or outcomes could be evaluated;
- relevant limitations or alternative explanations.

Please avoid presenting a model output as a prediction or as proof that a policy or social system will work in the real world.

## Pull requests

Once code contributions are enabled, keep each pull request focused and explain:

- what changed and why;
- how the change relates to an agreed research question or model specification;
- how it was checked, including any known limitations.

Update documentation when a change affects assumptions, model behavior, inputs, outputs, or reproducibility. Do not include secrets, personal data, or data that you do not have permission to share.

## License status

The project has not selected a software license or contribution terms yet. Until these are published, please use issues for ideas and feedback and do not submit code pull requests. The project will clarify how code and documentation contributions are licensed before accepting them.

## Questions

Open an issue in the repository for project questions or proposals. Please keep discussions focused on the project's scope and on evidence that can be examined by other contributors.
